## Featured Projects

### Calico – Full-Stack Productivity & Lo-Fi Music Application

**Live Application:** https://calico.nazmulhussain.co.uk

**Frontend:** https://github.com/Nazmul5765/calico-frontend

**Backend:** https://github.com/Nazmul5765/calico-backend

**Tech Stack:** C# | ASP.NET Core | Blazor | Entity Framework Core | SQLite | Azure SQL | Supabase Authentication | JWT | YouTube API | Docker | Railway | GitHub Actions

Originally developed as a collaborative team project during the Northcoders Enterprise Engineering Bootcamp:

- Collaborated in a team to develop a full-stack productivity and lo-fi music application featuring music search, playlists, timers, projects and user accounts
- Pair programmed on YouTube API integration and music search functionality across the ASP.NET Core backend and Blazor frontend
- Developed a Pomodoro-style timer prototype integrated with music playback controls and task-tracking functionality
- Contributed to repository, service and controller development using ASP.NET Core and Entity Framework Core
- Participated in test-driven development (TDD), writing and maintaining unit tests using NUnit, Moq and Shouldly
- Implemented custom API and database health checks to monitor application availability
- Worked using Agile practices including daily stand-ups, sprint planning, ticket management and collaborative Git workflows
- Contributed to dashboard functionality and user interface improvements using Blazor

Since the bootcamp, I've gone back to Calico independently and taken it from a group project to genuinely deployed, production software:

- Carried out a full security review of the backend and fixed what it found, including an IDOR vulnerability that let any logged-in user view or edit other users' projects, and a mass-assignment flaw that let users self-promote to admin
- Rebuilt login and signup to work correctly with Supabase authentication, connected the dashboard to the real logged-in user instead of a placeholder, and implemented a working logout
- Restored the real YouTube API integration, which the team had replaced with a hardcoded list of results due to API quota limits, and added a caching layer to manage quota properly
- Added accessibility improvements across the frontend, including ARIA labels on icon-only controls, decorative icons hidden from screen readers, and keyboard navigation support
- Merged in and finished an unfinished Pomodoro timer feature from an old branch
- Set up GitHub Actions CI for both the frontend and backend, and deployed both as Dockerised services on Railway, with Azure SQL in production

### Record Shop – Full-Stack Record Shop Application

**Live Application:** https://recordshop.nazmulhussain.co.uk

**Frontend:** https://github.com/Nazmul5765/record-shop-frontend

**Backend:** https://github.com/Nazmul5765/record-shop-api

**Tech Stack:** C# | ASP.NET Core | Blazor | Entity Framework Core | PostgreSQL | SQL Server | NUnit | Moq | Shouldly | Docker | Railway | GitHub Actions

Developed as my solo project during the Northcoders Enterprise Engineering Bootcamp and subsequently prepared for production deployment.

- Built a full-stack record shop application using ASP.NET Core and Blazor
- Developed a RESTful API with CRUD operations for managing records
- Used a layered Controller, Service and Repository architecture to separate application responsibilities
- Built reusable Blazor components with routing, forms and navigation
- Integrated the frontend and backend using HttpClient and REST API communication
- Implemented record browsing, searching, creation, editing and deletion functionality
- Used Entity Framework Core for data access, with PostgreSQL in the deployed application and SQL Server during development
- Applied automated testing using NUnit, Moq and Shouldly across the application layers
- Added custom health checks to monitor API and database availability
- Containerised the application using Docker and deployed it to Railway with PostgreSQL for production data storage
- Set up a GitHub Actions CI pipeline for both frontend and backend, building (and for the backend, testing) automatically on every push
